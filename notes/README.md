# DCMA 工业数据分析 Agent

基于 Pi SDK 的电机与变频器数据分析工作台，结合只读 MySQL 查询、程序统计、工业知识检索、证据绘图和报告交付，支持通过自然语言分析指定设备和时段的数据。

更新日期：2026年10月29日。当前为本机运行的工业分析原型，聊天页与七页监控展板由同一服务提供。已有20项工业工具、5份工业 Skill，以及四份资料组成的856条 RAG 语料；真实设备根因诊断、长期运行和生产部署仍待验证。

本机实际应用源码位于独立仓库 `D:\DCMA-Agent\pi`；外层 `D:\DCMA-Agent` 保存个人记录和旧展板。运行当前工作台时从 `pi` 启动。

## Agent 能力与近期优化

| 能力 | 当前实现 |
| --- | --- |
| 查询与统计 | 按设备和时段查询，程序计算指标、条件采样点数、窗口差异及代码事件；长窗口指标采用数据库聚合，代码事件采用流式统计 |
| 结构化交付 | 新增 `submit_analysis`，模型选择本轮证据和结论类型，程序校验并生成数值、单位、时间范围和手册出处 |
| 知识检索 | 语义与关键词混合检索，故障码精确匹配；嵌入服务或索引不可用时降级到关键词检索 |
| 证据与图表 | 成功查询形成固定证据，程序生成折线、散点、柱状图或直方图；历史会话恢复原快照 |
| 报告与导出 | 简要分析、完整运行报告、离线HTML报告，以及Markdown、PNG、SVG、CSV等导出；Windows使用本机“另存为”窗口 |
| 会话与反馈 | 本机保存会话，刷新续接任务，切换会话后继续后台生成，展示工具步骤、耗时和失败原因 |

最近重点修复了以下问题：

- 一周故障／报警统计因读取原始明细超过20000行而失败；流式事件统计不再依赖该明细上限。
- A07089手册内容混入相邻故障、F30001跨页内容不完整，以及错误检索条件被误报为未命中。
- 把查询覆盖等同于采样连续、把本页事件规律推广到全期、把观察跨度写成停机时长等证据范围问题。
- 10月29日修复同一回答中手册释义和适用性提醒重复的问题；保留不同来源和不同释义。

结构化交付失败允许一次修正，仍失败则降级为可核对的事实。没有统一尺度、基线或区间对齐计算时，不能交付稳定性排名、偏高偏低或报警影响判断。一般说明和澄清仍允许自由文本，该门槛不覆盖所有自然语言回答。

## 页面功能

| 页面 | 功能 |
|---|---|
| 设备概览 | 当前设备、运行信息、按8组分类的29个完整参数、电机与变频器插图 |
| 实时数据 | 设定/实际转速与转矩对比、18项指标单项趋势、六个半圆仪表 |
| 运行指标 | 按运动、电气、功率、温度、负荷查看18项指标，点击进入对应趋势 |
| 故障与报警 | 当前代码、全历史事件、北京时间范围查询、汇总、代码分布和分页 |
| 采样明细 | 所选设备最近50、100或200条原始记录，数值最多显示两位小数并居中，可按分组查看 |
| 数据查询 | 按北京时间查询历史采样，分页查看同步趋势与29字段明细 |
| 系统配置 | 保留八个子菜单；设备配置只读展示来源，通信配置可编辑并保存到当前浏览器 |

系统配置页（`#settings`）保留系统状态、授权配置、设备配置、监控配置、通信配置、自定义实时数据、语言/Language、其他设置八个子菜单。设备配置（`#settings/device`）只读展示模拟／历史来源和已取得的设备标识、最后采集时间，不将读取成功当作设备在线。通信配置（`#settings/communication`）支持协议启用、服务器地址/端口/用户名、发送周期、订阅主题和参数勾选/命名；其余六页内容待补充。通信配置只保存到本机浏览器，不连接 MQTT、不发送数据、不修改数据库；密码不持久保存。数据记录提供参考图可见的20项参数，逆变器数据采用现有29个展示字段；ALM/SLM/BLM参数列表待补充。原“数据说明”页面已移除，旧`#guide`和`#communication`地址显示系统配置中的通信配置。

左侧选择“查看设备”后，六个监控页面均以这一台电机为查看对象；系统配置中的通信配置单独保存到当前浏览器。切页保留设备、来源和采样条数选择；最新值与近期采样每3秒检查一次，支持手动刷新。“数据查询”单独选择起止时间，按50/100/200条分页，趋势仅展示当前页；历史采样手动查询，“返回实时”恢复自动刷新。历史异常独立每30秒检查一次，也可以点击“查询异常”。

实时页新增事件列表，从当前采样窗口合并故障/报警代码，显示日期、时间、事件和原始代码，最多展示最新50个事件。采样趋势右侧提供下载PNG、全屏查看（可退出）和数据视图；表格与当前曲线使用同一批采样，保留0、负数、缺失和数值精度，导出图包含设备/来源、时间范围、指标名称及单位。历史查询页沿用相同图表工具，只导出或查看当前页曲线。

故障与报警页的“历史代码分布”下方新增按代码累计的时长条形图，以分钟显示当前筛选事件的完整跨度，未结束只统计已观察时段，汇总不受明细分页影响。

## 已有本机环境：启动工作台

如果本机已配置依赖、模型授权和数据库，在一个 PowerShell 窗口执行：

```powershell
cd D:\DCMA-Agent\pi
npm run web:dev
```

打开 [Agent聊天页](http://127.0.0.1:3000/) 或 [监控展板](http://127.0.0.1:3000/dashboard/)。保持终端运行，按 `Ctrl+C` 停止。服务已运行时直接打开链接，不必重复启动，也无需单独启动旧展板的3001服务。

| 服务 | 地址 |
|---|---|
| Agent聊天页 | http://127.0.0.1:3000/ |
| 监控展板 | http://127.0.0.1:3000/dashboard/ |
| 服务与模型元数据 | http://127.0.0.1:3000/api/health |
| RAG索引状态 | http://127.0.0.1:3000/api/knowledge/health |

统一服务默认只监听本机，端口可通过 `DCMA_PORT` 调整。`127.0.0.1` 指打开浏览器的这台电脑，其他电脑不能直接通过这个地址访问本机工作台。

## 新电脑：首次准备

### 1. 环境要求

- Node.js 22.19.0或更新版本，以及随附的 npm。
- Git，用于克隆应用源码。
- 能访问数据库的校园网或对应 VPN。
- 数据库连接账号和密码；这些配置不包含在 Git 仓库中。

Agent对话需要可用的模型授权；数据库查询需要数据库配置和网络连通。语义检索另需嵌入服务配置，未配置时仍可使用关键词检索。

### 2. 获取项目与安装依赖

以下以本机相同的 `D:\DCMA-Agent\pi` 为应用位置；若使用其他目录，调整后续路径。已有源码时跳过克隆步骤。

```powershell
git clone https://github.com/JACK-Chen415/DCMA-pi-Agent.git D:\DCMA-Agent\pi
cd D:\DCMA-Agent\pi
npm ci --ignore-scripts
npm --prefix dashboard ci --ignore-scripts
```

应用根目录安装Pi及工作台依赖，`dashboard`另安装展板依赖；首次克隆缺少模型数据文件时，按工作台说明执行 `npm run hydrate:model-data`。

### 3. 配置模型、数据库与知识检索

在应用根目录执行，只在配置文件不存在时复制示例：

```powershell
if (-not (Test-Path packages/web/.env)) {
    Copy-Item packages/web/.env.example packages/web/.env
}
```

编辑 `packages/web/.env`，核对以下配置：

| 配置项 | 用途 |
|---|---|
| `DEEPSEEK_API_KEY` | 使用随项目配置的DeepSeek模型时填写对应授权 |
| `MYSQL_HOST` | 数据库主机 |
| `MYSQL_PORT` | 数据库端口，默认3306 |
| `MYSQL_USER` | 连接账号 |
| `MYSQL_PASSWORD` | 连接密码 |
| `MYSQL_DATABASE` | 展板使用的数据库，当前为 `dcma` |
| `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL` | 可选，独立于聊天模型的嵌入服务；支持RAG语义检索 |

修改配置后重启服务，网页设置中选择可用模型。保留已有配置，不将账号密码放进前端或提交到 Git；`.env` 已被忽略。随附知识库已有856条语料及向量索引；资料或嵌入模型变更后需检查匹配状态，构建向量会调用嵌入服务。详细配置见[工作台README](https://github.com/JACK-Chen415/DCMA-pi-Agent/blob/main/packages/web/README.md)。

### 4. 启动

按上面的“已有本机环境”步骤执行 `npm run web:dev`，然后打开聊天页或展板。

## 主要显示规则

### 时间、数值与字段

- 采集时间、入库时间、查询时间分别展示，处理后的时间统一显示为北京时间；原始时间字段保留原值。
- 历史异常和数据查询的起止时间使用日期选择与24小时输入，支持 `18:30` 或 `18:30:00`。仅结束时间有“现在”，点击填入当前北京时间，不自动提交；数据查询起止时间必填，历史异常允许只设一侧边界。
- 页面字段名称使用中文，单位按已确认参考资料标注，不进行数值换算。
- 页面展示29个字段，已隐藏状态码和系统运行时间；数据库与接口仍保留31个原始字段。
- 有效0和负数保留，缺失显示“—”；趋势在缺失处断线，不补0。
- 卡片和仪表读数最多显示4位小数，完整参数和采样表的数值最多显示两位小数，采样表数值居中；编号、时间和代码保留原值，接口原始精度不变。
- 同一选择查询失败时保留上次成功结果并提示；切换设备时清空旧结果，取消旧请求，避免混入上一设备的数据。

### 六个仪表

| 指标 | 单位 | 显示范围 |
|---|---|---|
| 实际转速 | rpm | −1500～1500 |
| 实际电流 | A | 0～3.3 |
| 实际转矩 | N·m | 当前有效采样范围；恒定值时扩展显示跨度 |
| 直流母线电压 | V | 0～1200 |
| 变频器温度 | °C | 0～150 |
| 电机温度 | °C | 0～150 |

五项固定量程来自参考图，实际转矩按用户确认保留原采样范围。超量程时指针停在边界，数字仍保留实际值。量程是显示范围，不是已确认的设备安全阈值。

### 故障与报警

非零故障码显示红色，非零报警码显示深黄色，代码文字保持原值。0只显示0，不附加“正常”；缺失显示“—”。

历史异常使用所选来源的全部有效历史采样生成，不受50/100/200条近期采样窗口限制：

- 同一字段连续出现同一个非零代码，合并为一次事件。
- 首次观察到非零代码作为开始；观察到归零或换码时结束旧事件。
- 没有观察到结束时保留“未结束”，持续时间只计算已观察到的跨度。
- 缺失代码不会作为恢复；开始前缺少可确认记录时标记“最早观察时间”。
- 时间查询匹配与区间重叠的事件，保留原有完整起止时间，每页50条。
- 汇总和代码分布统计整个筛选结果的事件次数；下方代码采样表展示近期记录，可单独按类型、代码筛选。

事件起止时间受采样间隔限制，历史记录依赖数据库原始采样保留，没有单独创建永久事件表。原来重叠的“历史异常时段”图已删除，起止时间和持续时间保留在事件表中。

## 常见问题

| 问题 | 处理方式 |
|---|---|
| 浏览器打不开3000端口 | 确认从pi目录启动的统一服务仍在运行，检查启动日志 |
| 页面能打开，但显示接口查询失败 | 检查后端终端、数据库配置和校园网/VPN连接 |
| 提示端口被占用 | 确认是否已有展板服务运行；若已运行，直接打开页面，不重复启动 |
| 历史真实数据时间较早 | 这是数据库中的历史采集时间；查询时间更新不代表采集记录更新 |
| 指定时间段查不到异常 | 核对设备、来源和数据库实际记录日期，也可以点击“全部时间” |
| 历史异常有记录，代码采样表却显示0条 | 两表范围不同：历史事件来自全部历史，代码筛选仅作用于最近50/100/200条；点击“重置筛选”可查看近期全部采样 |
| 电机2～4不能选历史真实采集 | 当前已确认的历史真实来源只属于电机1 |
| 重启电脑后页面打不开 | 从pi目录重新执行 `npm run web:dev` |
| 模型可选但回答失败 | 模型列表只说明元数据可用，核对所选模型授权、网络和具体错误 |
| RAG只返回关键词结果 | 检查知识健康接口中的嵌入配置、索引匹配状态和降级原因 |

## 当前状态与待确认事项

当前已实现展板、工业数据工具、资料检索、证据图表、报告及本机会话保存，数据库保持只读。知识库可提供代码释义，但参考手册可检索不代表适用于现场设备；真实型号、额定值、状态规则及部分特殊字段仍需确认。

稳定性统一比较、报警区间与指标关联尚无对应算法实现；真实语音、长期后台监测、正式工单流转、用户角色权限和生产运行仍待完善。当前不执行现场设备控制，不发送外部通知，不因故障事件为0就判断设备整体健康。最新优化与本次验证见[2026.10.29优化](2026.10.29优化.md)，历史过程见[HANDOFF](HANDOFF.md)。
